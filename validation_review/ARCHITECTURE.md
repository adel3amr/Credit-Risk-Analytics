# V5 source and data architecture

| Layer | Frozen source | Data / output contract |
|---|---|---|
| Portfolio generator | `scripts/generate_sme_portfolio.py` | 12k borrowers and 432k monthly observations; seeded; `data/raw/`. |
| Workout generator | `scripts/generate_lgd_workout_history.py` | 8k resolved default facilities with dated net cash flows and synthetic loss target; separate from active portfolio. |
| Borrower PD | `src/data_preparation.py`, `src/pd_model.py`, `notebooks/credit_risk_pipeline.py` | Approved financial/current conduct/qualitative fields → fixed logistic 12m PD on held-out borrowers. |
| EWS/stage/ratings | `src/early_warning.py`, `src/ecl.py`, `src/scorecard.py`, `src/governance.py` | Monitoring direction and distinct Stage 1/2/3 and internal 1–10 rating; fixed synthetic macro odds overlay. |
| Facility recovery model | `src/lgd_model.py`, `notebooks/lgd_model_pipeline.py` | Workout history → fixed champion validation and full-sample refit; `models/lgd_workout_model.joblib`; current facility LGDs. |
| Exposure and provision | `src/lgd_model.py`, `src/facility_ecl.py`, pipeline | Borrower products → individual facility EAD/term/LGD → stage-specific ECL → borrower and portfolio sums. |
| User workbench | `app.py` | Generated CSVs → portfolio/borrower/risk-management and validator views; demonstration role picker only. |
| Release | `scripts/run_v5.py`, `scripts/validate_v5.py`, `scripts/test_dashboard.py`, `.github/workflows/` | Complete generator/model/validation order; 30 release checks; interface smoke. |
| Independent review | `validation_review/tools/` and `tests/test_review_policy_edges.py` | Separate arithmetic and policy oracle outputs; reads frozen snapshot, no model refitting or parameter changes. |

**Current flow:** raw borrower data and behavioral observations feed PD, EWS and current stage; resolved workout history trains and tests LGD; reporting borrower products are expanded to facilities; scenario PD and facility LGD/EAD/term yield ECL by stage; facility totals are rolled to borrower and dashboard. The dashboard reads files generated by the batch pipeline; it is not an always-on scoring API. A reviewer should rerun the full generator and pipelines before launching the app. Generated CSVs and model artifacts are local outputs, not production records and not committed twice in the review branch.

Historical topology is documented in `PROJECT_TIMELINE.md`; the capability matrix is `VERSION_EVOLUTION_MATRIX.md`. The application exposes stored diagnostics but has no active authentication, service-level monitoring or independent staging event ledger.
